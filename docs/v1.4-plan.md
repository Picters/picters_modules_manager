## Prepared scenario pack and persistence

- The pure Dart pack prepares every supplied ODM scenario and omits unchanged
  maps/scenarios. A malformed baseline rejects the whole set.
- All custom ciphertext must round-trip before a deployment set is returned.
  This is an in-memory preparation step, not a filesystem deployment.
- Keep after reboot changes made during thermal application wait for that action
  and retain the latest choice without replacing its new temperature/profile.
- Eventual custom overrides belong in `/data/vendor/thermal/config`; ODM stock
  policies remain the baseline. Runtime activation, transactional file writes,
  restore ownership and reboot recovery are not yet integrated.

## Thermal file backend added

The app now has an Android thermal transport, wired through the production
repository factory. It reads installed ODM baselines, generates every applicable
scenario, encrypts with the native codec, checks round trips and root-file
readback, then calls the matching pack's PMM_THERMAL_FILES_V1 helper.

The helper journals its file transaction, preserves unrelated files, restores
original overrides, checks managed-file ownership by digest, rolls back on
service-restart failure, and recovers an interrupted swap at boot. Module hooks
run nonpersistent restoration at post-fs-data and restoration on uninstall.

Access now uses the captured mi_thermald loader hash and matching pack/kernel
APIs; a manually issued verified-device file is no longer required. This is a
source/ABI compatibility gate, not evidence of successful device activation.
The user opted to proceed without additional phone runs.

Charging targets now use a dedicated, leased MCA normal-vote adapter plus a
root policy worker. This avoids the no-op current_limit handler and permits
removing the app client through mca_vote(false). See sm8850-charging.md for
scope, approximate W semantics and the captured-vendor-only runtime gate.
The signed Android arm64 APK compiled successfully; Rust tests passed.
Kernel/adapter compilation and hardware behavior are not yet verified.
